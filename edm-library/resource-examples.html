不是“下载一个模板”，而是把参考库转成可复用模块。

下面每一例都对应当前的邮件任务：黑五促销、AI Assistant 激活、套餐选择和 SaaS 生命周期。

使用原则借：结构、兼容性写法、内容层级。
不借：原品牌、图片、文案、链接与未经确认的许可素材。
EXAMPLE 01 · COLORLIB + LEEMUNROE

黑五活动邮件：定全局模板风格，再填内容模块

Colorlib 适合定义整封营销邮件的视觉骨架：600px 内容宽度、首屏比例、间距、按钮、浅色分区、页脚。Leemunroe 则提供更稳妥的 HTML 容器、CTA 和内联样式底座。

  • 先把一整封邮件的视觉规则定为一个 Octoparse 基础模板，而非只取首屏。
  • 之后再按活动替换 Hero、功能说明、价格卡或优惠提示；页头、按钮和页脚不再重复设计。
  • 发往 Mailchimp 前，将 CSS 内联并给 Gmail、Outlook 各发一封测试。

EXAMPLE 02 · KONSAV

AI Assistant 邮件：仅在需要解释步骤时使用

对，三步说明只是一个“按需模块”，不是每封邮件的固定组成。konsav 的价值在于它提供了这种稳定的响应式信息排布。

  • 适用：首次上手、产品新功能、任务流程、试用激活。
  • 不适用：纯促销、到期提醒、价格直推或单一 CTA 邮件。
  • 没有明确步骤时，改用「一个价值主张 + 一个证明点 + 一个 CTA」即可。

EXAMPLE 03 · CERBERUS

复杂排版都用它验：价格卡只是最直观的一例

Cerberus 不是价格模块库，而是邮件兼容性底座。凡是需要在 Outlook/Gmail 内稳定呈现的双栏、图文卡、对比表、按钮、背景色区块，都应优先参考它的写法。

  • 示例中的价格卡：验证双栏不塌、按钮可点、移动端能顺序堆叠。
  • 同一套模式也可用于「功能对比」「两条案例」「左右图文」与「两个 CTA」。
  • 最终原则：视觉设计可自由，但输出 HTML 应落在 Cerberus 类兼容写法上。

EXAMPLE 04 · POSTMARK

试用用户：一条完整的 SaaS 生命周期序列

Postmark 更适合学习 SaaS 的“低营销噪音”写法。下面是可直接作为 Octoparse 试用用户起点的七封序列：每封只推动一个下一步，不把促销塞进每一次沟通。

  • 产品价值邮件与营销优惠邮件分开管理，避免黑五打断正常激活路径。
  • 每封邮件都应由实际行为触发或停止，而不是机械按日期群发。
  • 用户已完成关键动作后，跳过相应提醒，进入下一阶段。
DAY 0

试用欢迎

一句话价值 + 输入 URL 的首个 CTA。

DAY 1

首次任务

未创建任务者：给一个明确示例。

EVENT

首次成功

任务成功后：解释下一步可扩展场景。

DAY 3

功能匹配

按使用行为推荐模板、云端或 AI Assistant。

DAY 5

价值证明

展示数据量、节省步骤或典型使用成果。

DAY 6

到期提醒

说明试用何时结束，以及保留工作流的方式。

DAY 7

套餐建议

按用量推荐 Basic / Standard；优惠只在此时辅助出现。

EXAMPLE 05 · MAIZZLE I18N

多语言产品：一套组件，输出各语言可发送 HTML

你们已有多语言产品，推荐直接进入工程化第二阶段：把结构、品牌样式与翻译文本分开。一个英文/法文/德文版本不是三封手工复制的 HTML，而是同一个模板的三个构建结果。

应该维护的内容

共享：Header、Hero、CTA、Footer、价格卡、URL 规则。
语言文件：主题、Preheader、标题、正文、CTA、法律文本。

避免的做法

从英文 HTML 复制一份再手改；几轮活动后会出现 CTA、链接、退订说明和价格不一致。

locales/en.json { "hero.title": "Find the right data route", "cta": "Try AI Assistant" } locales/de.json { "hero.title": "Finden Sie den richtigen Weg zu Ihren Daten", "cta": "AI Assistant testen" } campaign.vue / MJML source <Heading>{{ $t('hero.title') }}</Heading> <Button>{{ $t('cta') }}</Button> 同一组件 + 各语言 JSON → en.html / de.html / fr.html → 分别导入 Mailchimp

最适合现在开始做的三件事

① 用 Colorlib / konsav 每次只挑一个“版式参考”；② 用 Cerberus 审核复杂双栏和 Outlook 风险；③ 把通过测试的模块写入 Octoparse 自有组件库。MJML 等工程化工具先作为第二阶段。
