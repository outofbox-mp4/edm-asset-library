下面每一例都对应当前的邮件任务：黑五促销、AI Assistant 激活、套餐选择和 SaaS 生命周期。

使用原则借：结构、兼容性写法、内容层级。
不借：原品牌、图片、文案、链接与未经确认的许可素材。
EXAMPLE 01 · COLORLIB + LEEMUNROE

黑五活动邮件：借版式，不复制整封

想做“产品价值在前、优惠在后”的黑五邮件时，Colorlib 用来找营销版式；Leemunroe 用来保证单列容器、CTA 和内联样式可靠。

  • 从 Colorlib 选择一张「大标题 + CTA + 促销条」的页面结构。
  • 把视觉内容换为 Octoparse 功能价值与自有 Banner。
  • 发往 Mailchimp 前，将 CSS 内联并给 Gmail、Outlook 各发一封测试。

EXAMPLE 02 · KONSAV

AI Assistant 邮件：借三步内容结构

konsav 的价值不在“视觉多潮”，而在经典响应式邮件的稳定排版。它很适合把复杂功能解释压缩成三步。

  • 把原有的长功能说明拆成三个短动作。
  • 每一步保持「编号 + 4–6 字标题 + 一句解释」。
  • 移动端会自动变成纵向阅读，不必硬塞复杂图文。

EXAMPLE 03 · CERBERUS

套餐选择：借 Outlook 安全的双栏结构

价格卡最容易在 Outlook 中并排失败。Cerberus 用于取经过验证的表格型双栏/混合布局写法，再填入自己的价格与 CTA。

  • 只给用户两个真正相关的选择，避免三到四档并排造成决策压力。
  • 使用表格布局和内联样式，避免依赖 flex、grid 或复杂圆角。
  • 每张价格卡只有一个 CTA，链接到对应套餐或活动页。

EXAMPLE 04 · POSTMARK

生命周期邮件：借信息优先级

Postmark 更适合学习 SaaS 的“低营销噪音”写法。例如试用开始、邀请、到期提醒、付款失败等，重点是清楚与可信，而非铺满促销元素。

  • 每封邮件只回答一个问题：下一步要做什么？
  • 把账户/产品事实放在第一屏，优惠只作辅助。
  • 将生命周期邮件与黑五促销邮件分开管理，不混用版式。

EXAMPLE 05 · MJML / MAIZZLE / REACT EMAIL

要不要上工程化？看维护方式，不看模板数量。

如果只是把已经验证的 HTML 粘贴到 Mailchimp，当前不必上框架；如果后续需要多语言、几十个版本、每周自动更新价格或由 Agent 批量产出，再考虑工程化。

现在：Mailchimp 工作流

在资产库选模板 → 替换文案/链接 → 粘贴 HTML → 测试 → 发送。

以后：工程化工作流

维护一个 MJML / Maizzle / React 源文件 → 自动生成多个分层 HTML → 测试 → 导入或 API 发送。

<mj-section background-color="#111827"> <mj-text font-size="28px" color="#ffffff"> Find the right data route </mj-text> <mj-button background-color="#1ff2cf"> Try AI Assistant </mj-button> </mj-section> MJML 源文件 → 编译为 HTML → 再进入 Mailchimp

最适合现在开始做的三件事

① 用 Colorlib / konsav 每次只挑一个“版式参考”；② 用 Cerberus 审核复杂双栏和 Outlook 风险；③ 把通过测试的模块写入 Octoparse 自有组件库。MJML 等工程化工具先作为第二阶段。
